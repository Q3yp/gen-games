# Live session evidence: rooftop rain tailor

This is one observed session, not a required story, benchmark or capability claim.
The initially empty world became a rooftop encounter with Vesper, a rain tailor.
An unplanned intention to loop thread around a basin produced newly invented
steering consequences through a live command, without source publication.

- First host response: 20.34 s, including one-time host-helper construction.
  Its server queue-to-commit span was 31 ms, not the full player wait.
- Next real **Steer away** button: 9,156.1 ms from same-browser input to command
  render. Separate measured spans were local input render 7.9 ms, event
  acknowledgment 20.3 ms, handler 1.2 ms and command acknowledgment 22.9 ms.
  These spans are not an additive breakdown of all host time.
- A generated raster background was imported through asset/work and bound without
  source release or remount; the server span was 25 ms. The same world survived
  server restart and browser reload. This does not establish a crash-safe browser
  offline outbox.
- Continuous local left/right steering was then authored and installed while
  preserving the world. Actual held keys overshot and corrected the heading,
  crossed the opening, and triggered a newly invented window encounter.
- Play exposed a handling problem: forward progress depended on turning. A
  subsequent code update added hands-free coasting and retained completed legs.
  The player chose to pass the window; the host honored that choice without
  forcing entry. A separately labeled controlled check also completed a coast
  with no held keys and no heading change.
- Both the background and a transparent character image arrived through guarded
  asset work. Source publication was used for new executable behavior, while
  ordinary narrative and visual updates used commands and asset bindings.
- Later richer world responses took 14.28–17.76 s. A 1,662-byte creative command
  received a 343-byte receipt; the earlier uncompressed path echoed a 1,591-byte
  command in a 1,552-byte reply and returned 12,858 bytes of command inspection.
  These are measured examples, not fixed token or latency guarantees.
- A deliberately stale live update returned `STALE_SCOPE` with expected/current
  versions and left the world unchanged. After the final engine reconnect, a
  short director command inherited its exact delivered guards and applied.
  Retrying its identical raw request after detach returned the original durable
  `APPLIED` receipt without another application or version advance.

Background work needs an actual running worker. A recorded job or acknowledged
handoff alone is insufficient; verify execution independently of the provider.

The evidence supports separating local play, semantic host responses, asset work
and new code installation. It does not prove that the game is instant, fun or
“addictive.” Judge new controls through actual input and consequences, and use
independent play when available rather than labeling timings as enjoyment.

The subsequent user correction explicitly prioritizes a balance of speed and
quality: optimize engine/tool token efficiency rather than generating less, and
accept longer work for complex visuals or mechanics. These timings should guide
removal of avoidable overhead, not impose a creative-output budget or shallow
mechanics. Progressive delivery is optional when it improves the experience.
